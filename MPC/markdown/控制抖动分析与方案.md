# 控制量抖动分析与解决方案

## 现象

修改 `sample_interval=1` 后，控制不再顶满，但转向角与转矩在步与步之间明显抖动，例如：
- Step 1: steer≈-0.9°, torque≈410 N·m  
- Step 2: steer≈16.2°, torque≈314 N·m  
- Step 3: steer≈-12.4°, torque≈973 N·m  
- Step 4: steer≈-0.07°, torque≈529 N·m  
- …

QP 每步均为 `status=optimal`，且 `tracking_err` 量级在 0.003～0.5 之间。

---

## 原因分析

### 1. 平滑项权重偏小（主因）

- 当前：`i_weights = 0.1`（控制增量惩罚），`r_weights = 0.01`（相对中性 0.5 的惩罚）。
- 代价 = 跟踪项（z 与 ref 的误差）+ R·(u-0.5) + I·(u[k]-u[k-1])。
- 跟踪项在 16 维 z 上、权重大（Q 前 6 维为 1.0），误差范数约 0.1～0.5 时，代价已较大；而 I=0.1 时，单步控制变化 0.2 的惩罚相对较小。
- 结果：优化器更倾向于“为减小跟踪误差而大幅改 u”，步与步之间 u 变化大，表现为控制抖动。

### 2. 参考窗与 warm start 不匹配

- 每 10 个 Simulink 步（decimation=10）解一次 MPC，解完后 `nearest_idx` 会更新，参考窗 `ref_r_6_rel` 随之平移并相对当前车位置重算。
- warm start 用的是**上一步**的整段 U_opt，但当前问题的 z0、z_ref 都已变化，初值并非“当前问题”的平移解。
- 未做“平移 warm start”（用上一步的 u[1:H] 再补最后一拍作为初值），所以初值对当前问题不够贴切，求解器容易收敛到与上一步差异较大的 u，加剧抖动。

### 3. 编码器与参考对微小差异敏感

- 每步的 `x_cur_for_enc`、`ref_r_6_rel` 仅有微小差异（位置、速度、yaw 等），但编码器非线性，z0、z_ref 可能随输入有小幅“跳跃”。
- 这些跳跃会改变 QP 的跟踪目标，从而放大 u 的步间变化。

### 4. 无输出侧滤波

- 当前直接把 MPC 本步的 u_opt[0] 经反归一化后送给 Simulink，没有对控制输出做时间上的平滑（如一阶滤波、滑动平均等），任何步间变化都会原样体现为转向/转矩抖动。

---

## 解决方案与调试思路

### 方案 A：增大控制平滑权重（优先）

- **做法**：在 `koopman_mpc_v2.py` 的 `KoopmanMPC.__init__` 中，将 `i_weights` 从 `0.1` 提高到 `0.5` 或 `1.0`（可做成可调参数）。
- **效果**：强化 (u[k]-u[k-1]) 的惩罚，使相邻两次 MPC 解出的 u 更接近，减轻抖动。
- **注意**：过大会使控制响应变“钝”，跟踪变慢，需在仿真里折中（例如先试 0.5）。

### 方案 B：控制输出一阶滤波（强烈建议）

- **做法**：在 `ddk_mpc_sfunction.py` 的 `compute_control` 中，对“实际下发”的控制做指数平滑，例如：  
  `u_out = alpha * u_prev_out + (1 - alpha) * u_mpc_current`，其中 `u_prev_out` 为上一步实际下发的归一化控制，`alpha ∈ [0.3, 0.6]`（如 0.4）。
- **效果**：不改变 MPC 内部逻辑，仅平滑输出，对 Trucksim 的转向/转矩指令更平滑，抖动明显减弱。
- **注意**：alpha 越大越平滑但延迟越大，可先取 0.4～0.5。

### 方案 C：平移 Warm Start

- **做法**：更新 warm start 时，不用“上一步整段 U_opt”直接作为本步 u_init，而用“上一步的 u[1:H] 再补最后一个 u[H-1]”作为本步的 u_init（即时间平移一拍的预测控制序列）。
- **效果**：初值更接近当前问题的解，QP 收敛更稳定，步与步之间 u 更连续。
- **实现位置**：在调用 `mpc.optimize` 前，若存在 `u_init_prev`，先做一次平移再传入。

### 方案 D：适当增大 R 权重

- **做法**：将 `r_weights` 从 `0.01` 提到 `0.02～0.05`（或对转向维单独加大）。
- **效果**：更强烈地把 u 拉向中性 0.5，减小大幅摆动，可与方案 A 同时使用。

### 方案 E：调试与验证建议

1. **打印步间控制差**：每步输出 `||u_opt[0] - u_prev||` 或 `max|u_opt[0] - u_prev|`，观察平滑项增大或滤波后是否明显下降。
2. **对比 ref 首点**：打印连续两步的 `ref_r_6_rel[0]` 和 `z_ref[0][:6]`，确认参考是否因 nearest_idx/编码器导致阶跃。
3. **先单改再组合**：先只加方案 A 或只加方案 B，看谁对抖动改善更明显，再考虑 A+B 或 A+B+C。
4. **decimation**：若抖动仍大，可尝试 decimation=20（每 20 步解一次 MPC），同一 u 保持更久，观感上会平滑一些，但跟踪会略滞后。

---

## 小结

- **根本原因**：平滑项 I 偏小 + 无输出滤波 + warm start 未平移，导致步间 u 变化大。
- **优先建议**：方案 A（增大 `i_weights`）+ 方案 B（输出一阶滤波），必要时再加方案 C（平移 warm start）和方案 D（略增 R）。

**已实现**：
- **方案 A**：`koopman_mpc_v2.KoopmanMPC` 的 `i_weights` 默认改为 `0.5`（原 0.1），可通过构造时传入 `i_weights` 调节。
- **方案 B**：`ddk_mpc_sfunction` 对实际下发的控制做一阶滤波 `u_out = alpha*u_last + (1-alpha)*u_mpc`，默认 `smooth_alpha=0.45`，可在 `initialize_controller(..., smooth_alpha=0.45)` 中修改。
- **方案 C**：warm start 使用平移序列 `[u_prev[1:H], u_prev[H-1]]` 作为本步初值。

# MPC 目录代码结构与调用关系

## 一、当前实际调用链（仅 V2）

```
Simulink (仿真步长 1 ms)
    │
    ▼
MATLAB Function 块（matlab_function_wrapper.m）
    │ 配置 param_path（.pth）、data_path（参考轨迹 .mat）
    │ 调用：initialize_controller / compute_control / reset_controller
    ▼
ddk_mpc_sfunction.py
    │ 仅 import koopman_mpc_v2（不 import ddk_controller）
    │ initialize_controller() → load_model()、KoopmanMPC()
    │ compute_control() → encode_state()、encode_ref_trajectory()、mpc.optimize()、convert_to_control_output()
    ▼
koopman_mpc_v2.py
    │ load_model、encode_state、encode_ref_trajectory、KoopmanMPC、convert_to_control_output、CONTROL_MIN/MAX_NP
    ▼
控制输出 [12 维] → Trucksim
```

## 二、文件作用与依赖

| 文件 | 作用 | 被谁调用 | 可删减 |
|------|------|----------|--------|
| **ddk_mpc_sfunction.py** | Simulink 用 Python 接口：初始化、算控制、重置 | MATLAB（matlab_function_wrapper.m） | 否，核心入口 |
| **koopman_mpc_v2.py** | 新 Koopman 网络 + 新 MPC（编码器、Koopmanv1、KoopmanMPC、QP） | ddk_mpc_sfunction | 否，核心实现 |
| **matlab_function_wrapper.m** | 嵌在 MATLAB Function 块里，配路径、调 Python | Simulink 模型 | 否，闭环必需 |
| **ref_trajectory/*.m** | 生成参考轨迹 .mat（直线/蛇形等） | 人工运行，产出给 data_path | 否，按需保留 |
| **ref_trajectory/test_structure.py** | 检查 .mat 中 ref_trajectory 结构 | 人工运行，调试用 | 可选，可保留 |
| **markdown/*.md** | 说明文档 | 无代码依赖 | 否，文档 |
| **requirements.txt / environment.yml** | 依赖列表 | 人工安装环境 | 否 |
| **ddk_controller.py** | 旧实现：DeepEDMD + MPCController（2 维 delta_u、6 维 ref） | 无（已无 import） | **可删**，已不用 |

## 三、适配“之前”Koopman MPC 的文件（可删减）

- **ddk_controller.py**：为**旧** Koopman-MPC 实现（DeepEDMD + MPCController），当前项目内**无任何引用**。  
  - 原由 `mpc_main.py`、`mpc_solve_analysis.py` 等调用，这些脚本已移除。  
  - **建议**：直接删除，简化目录；若需旧逻辑可从版本历史恢复。

其余文件均为当前 V2 闭环或文档/配置，不建议删减。
